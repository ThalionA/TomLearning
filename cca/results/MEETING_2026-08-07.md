## Shared pipeline (identical for every item unless stated)

Every analysis below starts from the same preprocessing, so it is stated once.

1. **Spike trains → rates.** Per animal, 1 ms spike trains, Gaussian smoothed at
   **σ = 2.5 ms**, binned to **10 ms** (`--bin-ms 10 --smooth-ms 2.5`). This is the
   canonical temporal-arm config (STATE.md §4).
2. **Engaged running bins only.** Keep bins that are in-trial (`trial_idx` not NaN) and
   **velocity ≥ 2 cm s⁻¹** (`cfg.velocity_thresh_cm_s`). Everything else is discarded.
3. **Area inclusion.** An area enters a pair only if it has **≥ 5 units**
   (`cfg.min_units`). Eight pairs: CA1-RSC, CA1-CA3, CA1-DG, CA1-V1, CA3-DG, CA1-SUB,
   RSC-SUB, V1-RSC.
4. **Third-area control.** For pair (X, Y), `Z` = the concatenated activity of **every
   other recorded area**, regressed out of both X and Y (`partial.partial_out_cv`).
   Where the readout is cross-validated, Z's coefficients are fit on **training trials
   only** — otherwise the "held-out" number is optimistic.
5. **Dimensionality reduction.** PCA to **k = 30** per area, fit on training rows only
   for the CV path.
6. **Cross-validation.** **5 folds, split by WHOLE TRIALS**, never by bins — within-trial
   bins are autocorrelated, so a bin-wise split leaks.
7. **Sample cap — and what "session" really means.** Sessions run to ~370 k engaged bins.
   Capped at ~**12 000 bins** by taking **consecutive within-trial blocks of ≤ 600 bins** from
   whole trials in turn. Consecutive, not strided: an even stride destroys bin adjacency and
   silently breaks segment-aware lag pairing (GOTCHAS.md).
   ⚠ **That cap stops at exactly 20 trials** (12 000 / 600). So the "session-level" analyses
   in items 2 and 3 are the **first ~20 trials**, not the whole session — for an animal whose
   learning point is trial 69 that window is entirely pre-learning. They describe *early
   behaviour*. The driver now prints the retained trial range. Epoch mode applies the cap
   *within* each 10-trial epoch instead.
8. **Sign convention.** **Positive lag ⇒ the FIRST-named area leads.** `lag_slice` pairs
   `X[t]` with `Y[t+lag]`, so at +50 ms in CA1-RSC, CA1 leads RSC.
9. **Unit of analysis.** **Animals-as-n**, paired *t* (`paired_stats.paired_t`). 8 pairs
   form a per-pair family with **no cross-pair correction** — the project's stated policy
   (STATE.md §3.0). n varies by pair (4–13) because not every animal has every area.

Both **FS-excluded and FS-included are co-primary** and reported throughout.

## Item 1 — Do different CCs have different IFI?

**Figures** `HCV1_perdim_ifi_{fsexcl,fsincl}_bin10` · `HCV1_perdim_ifi_cc1vstail_*`
**Code** `src/tom_cca/perdim_ifi.py`, `scripts/analyze_perdim_ifi.py`
**Data** `results/perdim_ifi_bin10{,_fsincl}.csv` (1497 / 1633 rows, 16 animals)

### What was done

No new fits. `run_lag_curves.py` had already exported the **held-out, segment-aware lag
curve for every canonical dimension** (dims 1–30 × lags ±25 bins = ±250 ms) into
`lag_curves_bin10*.csv`. This item re-reduces that file.

1. Group the long file by (animal, pair, dim).
2. For each dim's curve, compute the **Information Flow Index**:
   `IFI = (mean CC at lag>0 − mean CC at lag<0) / (sum)`, with **CC clipped at 0** (a
   negative held-out CC means "no coupling", not "reverse coupling") and **lag 0
   excluded** (it is neither direction). Returns NaN — not 0.0 — if one side is empty.
3. Three tests per pair, animals-as-n:
   - **CC₁ vs the significant tail**: paired *t* on `IFI(CC₁) − mean IFI(significant dims ≥ 2)`.
   - **Sign agreement**: per animal, the fraction of significant tail dims whose IFI
     shares CC₁'s sign; one-sample *t* against the 0.5 chance level.
   - **Rank trend**: random-slope LMM `ifi ~ dim + (1+dim|animal)` over significant dims.

### Result — no

- **FS-excluded: 0/8 pairs** show a CC₁-vs-tail difference at p < 0.05.
- **FS-included: 1/8** — RSC-SUB, Δ = −0.056, p = 0.039, **n = 3**. That is 1 of 16 tests.
- Sign agreement 0.25–0.86, **nothing significant** (min p = 0.063).

### Caveats — one of them changes how other things must be read

- **`dim` is canonical RANK, not a tracked component.** `heldout_lag_curve_flat_perdim`
  refits CCA at every lag, so "dim 2" at −100 ms and at +100 ms are the second-ranked
  dimension *of two different fits*. This is a statement about rank.
- **The `sig` flag is much weaker than it looks.** Significance is scattered across all 30
  ranks. Held-out CC does fall with rank (0.170 → 0.045 → 0.024, Spearman −0.66), but only
  **~44 % of significant dims sit at rank ≤ 5**, ~10–15 % sit beyond rank 20 where CC is at
  the floor, and the significant set is a contiguous leading run in only **~half** of cells.
  Cause: `subspace_window._significance` thresholds every dim against the **dominant-dim**
  circular-shift null (100 shuffles, α = 0.05), which is tiny in a weakly-coupled cell, so
  floor-level dims clear it. **Never select on `sig` alone.** This is why item 2 defines
  FF/FB by fit lag rather than by per-dim IFI sign.

## Item 2 — Separate subspaces into FF/FB

**Figure** `HCV1_lagsubspace_fffb_{fsexcl,fsincl}_bin10`
**Code** `src/tom_cca/lag_subspace.py`, `scripts/run_lag_subspaces.py`, `analyze_lag_subspaces.ff_fb`
**Data** `results/lag_subspaces_bin10{,_fsincl}.csv` (1491 / 1533 rows, 16 animals)

### What was done

Nothing previously exported CCA **weights** at a lag — only correlations — so the subspace
itself had never been compared across lags. New module.

1. **Segment-aware lag.** `segment_lag` pairs `X[t]` with `Y[t+lag]` **within each trial
   only**; the |lag| bins that would pair the end of one trial with the start of the next
   are dropped. The confound is returned **twice, aligned to each area's own timepoints** —
   partialling a third area out of Y using Z at X's times would inject exactly the lag
   being measured.
2. **Fit at a fixed lag** (`lag_sweep`), leak-free: confound regression and PCA fit on the
   **unlagged training trials**, CCA fit on training and read on held-out. Both are hoisted
   out of the lag loop — lagging only selects rows, so coefficients are unchanged. This is
   ~20× cheaper *and* means every lag shares **one neuron→PC basis**, so a cross-lag angle
   reflects CCA rotation rather than refitted-PCA jitter.
3. **FF = the fit at +5 bins (+50 ms), FB = the fit at −5 bins (−50 ms)** — the report's
   headline IFI window. Defined by **fit lag, not by per-dim IFI sign**, because item 1
   showed the significant tail is dominated by floor-level dims where the sign is near a
   coin flip; tagging dims would be noise-splitting followed by a circular test.
4. **Three contrasts**, animals-as-n paired *t*: `cc₁(FF) − cc₁(FB)`;
   `gini_conn(FF) − gini_conn(FB)` using the **connection-specific** Gini
   (`subspace_contribution_connection` — the partner-invariant one is a GOTCHA); and the
   **principal angle between the FF and FB subspaces vs the split-half noise floor**.
5. **The angle** (`subspace_angle`): QR-orthonormalise both weight matrices, take
   `scipy.linalg.subspace_angles`, report the **largest** angle in degrees — so a subspace
   matching on its dominant axis but diverging elsewhere is not scored as stable.
6. **The floor** (`split_half_floor`): split trials in half, fit each half at the same lag,
   take the angle between them. **A separate floor per area** — the floor rises with fewer
   units and these pairs are lopsided (CA1 vs SUB).

### Result — the split is not supported

| test | FS-excluded | FS-included |
|---|---|---|
| FF/FB angle clears the floor | **0/8 pairs** | **0/8 pairs** |
| connection-specific Gini differs | 0/8 | 0/8 |
| cc₁ strength differs | 1/8 (RSC-SUB, p = 0.045) | 1/8 (CA1-RSC, p = 0.015) |

The two strength hits land on **different pairs** in the two conditions — 2 of 16 tests at
α = 0.05, i.e. chance. **At ±50 ms this is one subspace read at two delays, not two
directions of flow.**

### But the strength through that one subspace IS time-asymmetric

`cc₁(+50) − cc₁(−50)` has the **same sign in 8/8 pairs across both FS conditions**, and the
intra-hippocampal three recover anatomy: **CA3→CA1, DG→CA1, DG→CA3**.

⚠ Two honest limits: FS-included is FS-excluded *plus* fast-spiking units, so the two share
most of their data — this is a **consistency check, not a replication**, and a binomial test
on 8/8 would be pseudoreplication. And per-animal sign consistency for those three pairs is
only 4/7, 6/11, 3/5 (≈ chance), so the group mean is carried by magnitude in a few animals.
The animal-consistent flows are **RSC→SUB (6/7)** and **V1→RSC (7/9)**.

## Item 3 — How stable/similar are the CCs across time lags?

**Figure** `HCV1_lagsubspace_stability_{fsexcl,fsincl}_bin10`
**Code** `analyze_lag_subspaces.stability` / `stability_width`
**Data** `results/lag_subspaces_stability_bin10{,_fsincl}.csv`

### What was done

Same sweep as item 2, over the lag grid
**0, ±1, ±2, ±3, ±4, ±5, ±7, ±10, ±15, ±20, ±25 bins** (= 0 … ±250 ms; 21 lags).
For each lag, the principal angle between the **lag-0 subspace** and the **lagged subspace**,
compared to that pair's own split-half floor, animals-as-n paired *t* on `angle − floor`,
**Bonferroni across the 10 distinct |lag| values within a pair**.

### The finding that nearly went wrong

At the originally-planned **3 canonical dims** the split-half floor is **~78°** — two halves
of the *same* data at the *same* lag come out near-orthogonal. The lagged angle is ~75°, so
it has **nowhere to go**, and "not different from floor" would have been reported as
"the subspace is stable". That is a **power failure, not a null**. The analysis now carries
an `estimable` flag (floor < 70°) that must be read before any p-value, and **CC₁ is
primary** — there the floor is ~53–56° with real headroom.

Switching the FF/FB gate to CC₁ for the same reason changed item 2's answer from
2/8 "separable" to **0/8**.

### Result — no detectable rotation with lag

- **No interpretable rotation.** With per-area floors (post-fix), 7/8 pairs FS-excluded and
  6/8 FS-included show no lag separating from the floor anywhere in ±250 ms.
- **The exceptions are noise.** CA1-DG at +100 ms (Δ = +20.2° / +20.3°, p(Bonf) = 0.023 /
  0.026) and CA1-CA3 (FS-included only). Bonferroni is *within*-pair across 10 |lag| values,
  so with 8 pairs ≈ 0.4 pairs are expected to hit by chance. And CA1-DG's angle-vs-lag profile
  is non-monotonic and jumpy — 17.0, 5.6, −0.2, 17.2, −2.5, … , 19.3, 10.0, 1.0, **20.2**,
  −1.8, 8.1, 17.4 — with several 15–19° values that do not cross. No lag-specific structure.
- **The informative tail is the OTHER one.** Three pairs FS-excluded (CA1-V1, RSC-SUB, V1-RSC)
  and one FS-included sit *significantly below* their floor. That is measured confirmation of
  the floor-inflation argument below, not merely an argument from §G.
- 3-dim floors ~77° (FS-excl) / ~74.5° (FS-incl): **retained only to document the power
  failure**, shown dotted in the figure.

### Caveat — the test is conservative by construction

The floor is measured from **half-data** fits while the comparison uses the **full window**.
Fewer samples ⇒ noisier subspace ⇒ larger angle, so the floor sits **above** the true noise
level of the comparison it gates. The report's own §G corroborates this: cross-window
rotations come out significantly *below* their floors. **So this excludes a large rotation,
not a modest one.**

## Item 4 — Separate lagged curves by FF/FB, and for naive/exp

**Figures** `HCV1_lagsubspace_evolution_{fs}_bin10` · `HCV1_lagsubspace_evolution_curves_{fs}_bin10` *(new)*
**Code** `run_lag_subspaces.py --epochs`, `analyze_lag_subspaces.ff_fb_evolution`
**Data** `results/lag_subspaces_bin10_epochs{,_fsincl}.csv` (3150 rows, 12 learners)

### What was done

The same lag sweep, resolved by learning epoch. **Learners only** — an epoch split needs a
learning point. Epochs from `dataio.epoch_windows` with **`trials_per_epoch = 10`**:

- **naive** = trials 1–10
- **intermediate** = the 10 trials ending at the learning point
- **expert** = the 10 trials after the learning point

**The sample cap is applied WITHIN each epoch, not to the session** — capping first would
spend the whole 12 000-bin budget on the earliest trials and leave the expert epoch empty.

Expert − naive, animals-as-n paired *t*, on four quantities: FF cc₁, FB cc₁, their
**asymmetry** `cc₁(FF) − cc₁(FB)`, and the FF/FB angle.

### Result — null in both FS conditions

**0/8 pairs** for the asymmetry change. Nothing significant in any of the 32 tests per FS
condition: **min p = 0.068** (FS-excl, V1-RSC feedback cc₁) and **0.056** (FS-incl, same).

### How to read it

Not "the two streams stay balanced" — **there aren't two streams.** Item 2 already showed FF
and FB are not separable subspaces, so a null on their difference is a statement about
variation *within one* subspace. The figure and table both carry that inline.

## Item 5 — One CC, lagged across time

**Figure** `HCV1_fixedsubspace_lagcurves_{fsexcl,fsincl}_bin10`
**Code** `src/tom_cca/fixed_subspace.py`, `scripts/run_fixed_subspace.py`
**Data** `results/fixed_subspace_bin10{,_fsincl}.csv` (12 learners, 153 curves per FS)

### What was done

Every epoch contrast in the project so far **refits** CCA within each epoch, so an epoch
difference can be a difference in the *fit* rather than in the *activity*. This removes that.

1. **Identify the subspace once**, on a trial set **balanced across epochs**
   (`balanced_trials`: take the smallest epoch's trial count, draw that many from each,
   deterministic per seed). Balance matters — an unbalanced fit would favour whichever
   epoch dominates it, destroying the symmetry the contrast depends on.
2. **Freeze the weights**, then **project each epoch through the identical map**
   (`project` applies the frozen weights *and* the fit-time centring, so any subset maps
   the same way).
3. **Lag one canonical component across time** (`variate_lag_curve`): Pearson correlation
   of `u[t]` with `v[t+lag]`, pooled **within trials only**, over **±25 bins = ±250 ms**.

⚠ **The resulting r is IN-SAMPLE** — the frozen fit saw every epoch. It is a **contrast
statistic, never a coupling strength**; the leak-free numbers are in item 2's arm. This is
stated in three places in the module so it cannot be quoted wrongly.

### Result — and an unlooked-for positive control

**The frozen component's lag curve rings at theta** — but the evidence is NOT the fraction of
curves that ring. ⚠ `side_peak` fires on **~100 % of pure-noise curves** at the `ratio > 0.5`
gate, so that fraction (originally quoted as 33–92 %) is worthless. The real evidence is
**where** the side peaks land, against a calibrated null (`side_peak_null`):

| | real | noise |
|---|---|---|
| median side-peak offset | **140 ms (7.1 Hz)** | 170 ms |
| IQR | 120–148 ms | 90–270 ms |
| fraction in the 5–12 Hz band | **85 %** | 37 % |

KS D = 0.38, **p = 2.7×10⁻¹¹** (FS-excluded; 1.3×10⁻¹⁰ FS-included). Theta, recovered without
the method being told about it — good evidence the projection tracks real dynamics.

## Item 6 — Lagged curves and integration windows, naive vs exp

**Figures** `HCV1_integration_window_anatomy_{fs}_bin10` · `HCV1_integration_window_summary_{fs}_bin10` *(new)* · `HCV1_fixedsubspace_windows_{fs}_bin10`
**Code** `fixed_subspace.curve_half_width` / `side_peak`, `analyze_fixed_subspace.py`
**Data** `results/fixed_subspace_epoch_bin10{,_fsincl}.csv`

### What was done

From each frozen-component lag curve:

- **`curve_half_width`** — the width of the **contiguous** region around the peak where the
  curve stays ≥ half its peak. Grown *outward from the peak* and stopped at the first bin
  below threshold, so a far-lag noise excursion above half-max cannot widen it.
- **`side_peak`** — the largest secondary peak outside that central region, requiring a
  **strict** local maximum on both sides (with `>=`, every point of a flat plateau
  qualifies — a test caught this).

### Result — the obvious reading is wrong

Raw widths look like a clean hierarchy of integration timescales:

| intra-hippocampal | hippocampal–cortical / cortical |
|---|---|
| CA1-DG 22 ms · CA3-DG 26 ms · CA1-CA3 29 ms | CA1-V1 183 ms · RSC-SUB 220 ms · V1-RSC 256 ms |

**It is largely a rhythm artefact.** On a ringing curve the half-max region is truncated by
the first theta trough, so the width is a **half-period, not an integration window**. Only
**V1-RSC (33 % ringing) and RSC-SUB (42 %)** fall below the majority line and have widths
readable as integration windows. The anatomy figure shows exactly this: the blue band is
what `curve_half_width` returns, the purple lines are the detected ring.

The summary panel deliberately **does not claim a width-vs-ringing correlation**: across
pairs Spearman ρ = −0.55, p = 0.154 (FS-excl) and −0.50, p = 0.207 (FS-incl), and pairs
share areas and animals so a cross-pair correlation is pseudoreplicated anyway. It
classifies pairs either side of the line, which is what the data supports.

### Epoch contrast — null, and the one candidate is weak

Expert vs naive on the width: **0/8 pairs FS-excluded, 1/8 FS-included** (CA1-RSC,
Δ = −205 ms, p = 0.029).

⚠ **That candidate does not survive a censoring check.** `width_ms` is bounded at **both**
ends — 0 ms when only the peak bin clears half-max, 500 ms when the curve never drops below
it. **~10 % of values sit at each bound; only ~78 % are interior.** Dropping the single
ceiling-censored animal takes CA1-RSC from **p = 0.029 (n = 8) to p = 0.068 (n = 7)**.
It does pass a different check — a low peak would lower the half-max threshold and inflate
width, but corr(peak, width) = **+0.78 / +0.80**, so the wide naive curves have *higher*
peaks. Net: direction consistent across both FS, significance resting on one censored point.
**Do not quote the significant version alone.** `censoring_report` / `width_robustness` now
print this warning automatically.

## Item 7 — Fixed subspaces across all trials, naive vs exp

**Figure** `HCV1_fixedsubspace_windows_{fsexcl,fsincl}_bin10` (+ the item 5 curves)
**Code** `analyze_fixed_subspace.reduce_curves` / `epoch_contrasts`
**Data** `results/fixed_subspace_stats_bin10{,_fsincl}.csv`

### What was done

Each frozen-subspace lag curve is reduced to four readouts — **peak r**, **peak lag (ms)**,
**IFI**, **half-max width (ms)** — and each is contrasted expert vs naive with an
animals-as-n paired *t*, per pair. 8 pairs × 4 metrics = **32 tests per FS condition**.

### Result — null

- **FS-excluded: 0/32** significant (i.e. **32/32 null** — an earlier log entry said 31/32).
- **FS-included: 0/32** significant post-fix. The former 1/32 (CA1-RSC width) was the artefact.

Because the weights are frozen and epoch-balanced, this is a test of the **activity**, with
the refit confound removed that every previous epoch contrast in the project carries. That
makes it the cleanest null of the set rather than the weakest.

## Cross-cutting things worth raising

1. **Three methodological traps** (all in `GOTCHAS.md`), each of which would have produced a
   confident wrong answer: `sig` cleared by floor-level dims at any rank; subspace-angle
   tests unmeasurable at 3 dims; half-max width on a ringing curve. The second flipped an
   answer before it was reported.
2. **Theta ringing** is the most robust thing in this set and was not looked for.
3. **Two discrepancies against STATE.md §3.0 finding 3**, to reconcile before write-up:
   CA1-SUB reads **CA1→SUB** here (5/7 animals) vs **SUB→CA1** there; and CA1→RSC is
   FS-fragile under this method (p = 0.015 FS-incl, p = 0.764 FS-excl) where §3.0 has it at
   p = 3.9×10⁻⁴. Different methods — subspace refit at a fixed lag vs IFI integrated from a
   single session-level fit — so not directly comparable, but not ignorable.
4. **`figs_report.fig_rotation_floor` plots the unmeasurable 3-dim angle.** The
   rotation-null verdict is safe (§G tests it at CC₁) but the figure should switch.
